# 읽을 수 있는 작업 화면

2026-09-06. 기준: main `fef5681` (PR #59–62 병합 확인).

## 배치 결정

- Requests를 왼쪽 사이드바 안의 접이식 섹션으로 배치한다. 기본 사이드바 너비는 350px이며 저장한 사용자 너비는 유지한다. Requests를 접으면 작업 목록 공간을 확보하고, 펼친 상태에서는 Requests 높이를 별도로 조절한다. 목록과 요청 이력은 각각 독립적으로 스크롤한다.
- Requests는 옅은 배경, 응답 필요 수, Open/All로 행동 대기 영역임을 구분한다. Messages는 아래쪽 대화 영역을 사용하며 Requests에서 agent 대화로 바로 이동할 수 있다.
- Agents 사용량/상한, queued, Today 토큰 추정치는 relay 로고가 있는 상단 헤더에 한 줄로 표시한다. 브라우저 favicon과 헤더에는 같은 Relay 아이콘을 사용한다. 작은 화면에서는 탐색·설정 조작 공간을 침범하지 않도록 반응형으로 표시한다.
- 좁은 화면에서도 작업 목록과 Requests에 접근할 수 있어야 하며, 패널 전환 시 메시지 DOM을 교체하지 않아 초안과 Ask 상태를 유지한다.
- 대화 영역의 기본 높이는 헤더·상태 배너를 제외한 작업 영역의 45%다. 작은 화면에서는 최소 240px를 목표로 하고 상단에 120px를 남긴다. 낮은 창에서는 그래프 도구를 두 열로 배치하고 범례를 숨겨 카드와 도구 공간을 확보한다. 사용자가 저장한 픽셀 높이는 유지하되 현재 창에 맞게 표시만 제한한다. 창을 다시 키우면 원래 선호 높이를 복원한다.
- 경계선 더블클릭 또는 Command palette의 `Reset conversation height`로 반응형 기본 높이를 복원한다. 다른 패널 크기만 저장해도 대화 높이가 고정되지 않도록 기본값은 `null`이다.

## 작업 상세와 대화 탐색

- Task detail은 기본적으로 닫힌다. 그래프 노드 또는 작업 목록을 선택하면 캔버스 안의 오른쪽 패널로 열리고, 닫으면 그래프에 공간을 돌려준다. 새로고침 시 저장된 작업 선택은 복원하되 상세 패널은 열지 않는다. 외부 세션 상세도 선택할 때만 연다.
- 사용자가 보낸 메시지와 그 접수·처리 표시는 오른쪽, agent가 보낸 질문·결과와 Relay 응답은 왼쪽에 정렬한다. agent 발신자는 이모지 아바타와 작업 ID를 묶은 pill로 표시하고, 시스템 발신자는 `Relay`로 표시한다. Requests에서는 요청의 상태와 이력을 훑고, Messages에서는 질문과 응답을 대화로 읽는다.
- agent의 질문 본문과 응답 선택지는 하나의 카드로 묶어 질문과 답변 조작의 관계를 분명하게 한다. 긴 선택지는 카드 안에서 줄바꿈한다.
- Requests 제목을 누르면 해당 agent의 가장 최근 메시지로 이동하고 키보드 포커스와 잠깐의 강조 표시를 준다. 이는 특정 과거 요청 시점의 메시지로 이동하는 기능이 아니다. 여러 agent로 분할된 요청은 각 작업 칩으로 개별 agent의 메시지를 찾는다. 아직 메시지가 없으면 그 사실을 알린다. 좁은 화면에서는 Messages를 볼 수 있는 상태로 전환한다.
- agent별 이모지 아바타와 색은 UUID 기반 해시로 정한다. 새로 렌더링하거나 새로고침해도 같은 agent의 요청·대화·노드·목록 표시가 일치한다. 이모지와 ID를 하나의 pill로 묶어 알아보기 쉽게 표시한다. 유한한 이모지·색 조합은 중복될 수 있으므로 작업 ID를 함께 표시하며 색만으로 구분하지 않는다.

## 그래프와 목록의 역할

목록은 전체 작업의 상태와 탐색을 담당하고, 그래프는 읽을 수 있는 크기로 현재 작업 주변 관계를 보여준다. 자동 배치는 카드 100% 크기를 유지한다. Alignment 설정은 제거해 화면 정렬을 별도로 선택할 필요가 없게 한다. 부모 카드는 320px, 자식은 300px, 대기 카드는 260px로 넓히고 제목을 최대 두 줄로 표시한다. 열 간격도 함께 넓히며 긴 제목으로 높이가 바뀌는 대기 카드도 실제 높이로 배치한다. Gateway는 대기 카드와 같은 260px 너비의 흰색 실선 카드로 통일한다. 두 카드의 오른쪽 경계를 맞추고 Gateway 연결은 tree/radial 모두 하나의 Bézier 곡선으로 그려 대기 카드와 겹치지 않게 한다. 포인터로 카드를 누를 때는 클릭이 끝나기 전에 포커스 처리로 카드가 이동하지 않으며, 키보드 포커스의 중심 이동은 유지한다. 목록에서 선택한 작업은 최소 100%로 이동하며, 수동 탐색 후 상태 갱신이 시점을 빼앗지 않는다. `Read`는 선택한 작업 또는 첫 작업에 자동 배치를 다시 적용한다. `Fit to view` / Home은 전체 관계를 살펴보는 축소 개요다. 60개 작업에서도 전체 범위가 들어가도록 개요 배율은 20% 아래까지 허용한다.

| 대안 | 판단 |
|---|---|
| 전체 그래프를 항상 맞춤 | 세션 증가가 곧 글자 축소로 이어져 기본 표시에서 제외 |
| 그룹 접기 | 부모·자식 관계는 이미 묶여 있으나, 접힌 자식의 질문·오류와 선택 상태를 표현하는 추가 규칙이 필요하므로 이번 범위에서 보류 |
| 선택한 작업만 필터링 | 관계 비교가 끊기므로 기존 주변 작업 강조와 목록 이동을 활용 |
| 그래프를 목록으로 교체 | 기존 상태별 목록과 중복되므로 두 영역의 역할을 분리 |

전체 작업을 동시에 읽는 화면은 아니다. 많은 작업은 목록으로 이동하고 전체 관계는 개요로 확인한다. 렌더링 가상화나 수백 노드 성능 최적화는 이 변경에 포함하지 않는다.

## 재현

```sh
RELAY_UI_AUDIT_PORT=18814 bun scripts/ui-audit/serve.ts
bun test web/test
bun run build:web
bunx tsc --noEmit
bun test
```

합성 서버는 현재 worktree의 HTML/JS/fixture를 매 요청마다 읽으며 실제 서버 어댑터를 로드하지 않는다.

- `/`: 질문, 긴 제목, 하위 작업, 외부 세션, 완료 요청
- `/?few`: 2개 작업
- `/?many`: 60개 상위 작업과 하위 작업
- `/?history`: 두 agent의 과거 요청·응답 24쌍을 추가한다. All 필터에서 긴 요청 이력의 독립 스크롤과 agent별 최신 메시지 이동을 확인한다.
- `/?empty`, `/?dark`, `/?updates`, `/?slow`, `/?fail`: 빈 화면·테마·반복 렌더·전송 대기·전송 실패
- `?updates`는 반복 렌더이며 상태 변경은 합성 질문 응답과 Stop/Restart/Archive로 확인한다.

브라우저에서 1440×900, 390×844, 736×414를 확인한다. 사이드바 너비와 Requests 접기·별도 높이 조절, 상단 사용량 요약과 favicon 일치, 독립 스크롤, 메시지 좌우 정렬, 요청에서 메시지로 이동·포커스·강조, agent 표시의 일관성을 검증한다. 상세 기본 닫힘·선택 시 열기·닫은 뒤 공간 반환·새로고침 시 닫힘도 확인한다. 기존 검증 대상인 헤더 정렬과 대화 높이, 노드 포인터 클릭·키보드 선택과 카드 너비·두 줄 제목·열 간격, Read/개요, Open/All, 질문 카드와 응답, 초안·Ask, Cmd+K/Esc, 모바일 전환을 유지한다. 기존 저장 높이와 초기 설정 없는 화면은 구분한다. 이 목록은 검증 계획이며 이번 수정의 통과 결과를 의미하지 않는다.

실제 설치된 Relay나 Claude 세션에는 적용하지 않는다. Vimium의 Esc 가로채기를 확인하는 issue #58은 별도 미해결 항목이며 이번 검증으로 종료하지 않는다.

가로 휠과 트랙패드 가로 스크롤은 캔버스를 이동하며 Shift+휠도 좌우 이동으로 처리한다. 일반 세로 휠과 Ctrl/Meta 수정 키를 사용한 확대·축소는 포인터 중심을 유지한다.
