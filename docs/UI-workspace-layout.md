# 읽을 수 있는 작업 화면

2026-09-06. 기준: main `fef5681` (PR #59–62 병합 확인).

## 배치 결정

- Messages 왼쪽 / Requests 오른쪽을 유지한다. 넓은 대화·입력 흐름과 기존 사용자의 위치 기억을 유지하면서, 두 패널이 각각 40px 헤더를 갖도록 한다. Requests는 옅은 배경, 응답 필요 수, Open/All로 행동 대기 영역임을 구분한다.
- 좁은 대화 영역에서는 Messages/Requests 탭을 사용한다. 메시지 DOM을 교체하지 않아 초안과 Ask 상태를 유지한다. Requests 탭에도 응답 필요 수를 표시한다.
- 대화 영역의 기본 높이는 헤더·상태 배너를 제외한 작업 영역의 45%다. 작은 화면에서는 최소 240px를 목표로 하고 상단에 120px를 남긴다. 낮은 창에서는 그래프 도구를 두 열로 배치하고 범례를 숨겨 카드와 도구 공간을 확보한다. 사용자가 저장한 픽셀 높이는 유지하되 현재 창에 맞게 표시만 제한한다. 창을 다시 키우면 원래 선호 높이를 복원한다.
- 경계선 더블클릭 또는 Command palette의 `Reset conversation height`로 반응형 기본 높이를 복원한다. 다른 패널 크기만 저장해도 대화 높이가 고정되지 않도록 기본값은 `null`이다.

## 그래프와 목록의 역할

목록은 전체 작업의 상태와 탐색을 담당하고, 그래프는 읽을 수 있는 크기로 현재 작업 주변 관계를 보여준다. 자동 배치는 카드 100% 크기를 유지한다. 목록에서 선택한 작업은 최소 100%로 이동하며, 수동 탐색 후 상태 갱신이 시점을 빼앗지 않는다. `Read`는 선택한 작업 또는 첫 작업에 자동 배치를 다시 적용한다. `Fit to view` / Home은 전체 관계를 살펴보는 축소 개요다. 60개 작업에서도 전체 범위가 들어가도록 개요 배율의 기존 20% 하한을 낮췄다.

| 대안 | 판단 |
|---|---|
| 전체 그래프를 항상 맞춤 | 세션 증가가 곧 글자 축소로 이어져 기본 표시에서 제외 |
| 그룹 접기 | 부모·자식 관계는 이미 묶여 있으나, 접힌 자식의 질문·오류와 선택 상태를 표현하는 추가 규칙이 필요하므로 이번 범위에서 보류 |
| 선택한 작업만 필터링 | 관계 비교가 끊기므로 기존 주변 작업 강조와 목록 이동을 활용 |
| 그래프를 목록으로 교체 | 기존 상태별 목록과 중복되므로 두 영역의 역할을 분리 |

전체 작업을 동시에 읽는 화면은 아니다. 많은 작업은 목록으로 이동하고 전체 관계는 개요로 확인한다. 렌더링 가상화나 수백 노드 성능 최적화는 이 변경에 포함하지 않는다.

## 재현

```sh
RELAY_UI_AUDIT_PORT=18814 bun scripts/ui-audit/serve.ts
bun test web/test
bun run build:web
bunx tsc --noEmit
bun test
```

합성 서버는 현재 worktree의 HTML/JS/fixture를 매 요청마다 읽으며 실제 서버 어댑터를 로드하지 않는다.

- `/`: 질문, 긴 제목, 하위 작업, 외부 세션, 완료 요청
- `/?few`: 2개 작업
- `/?many`: 60개 상위 작업과 하위 작업
- `/?empty`, `/?dark`, `/?updates`, `/?slow`, `/?fail`: 빈 화면·테마·반복 렌더·전송 대기·전송 실패
- `?updates`는 반복 렌더이며 상태 변경은 합성 질문 응답과 Stop/Restart/Archive로 확인한다.

브라우저에서 1440×900, 390×844, 736×414를 확인한다. 헤더 정렬과 대화 높이, 목록 선택 후 카드 크기, Read/개요, Open/All, 질문 응답, 초안·Ask, Cmd+K/Esc, 모바일 전환이 검증 대상이다. 기존 저장 높이와 초기 설정 없는 화면은 구분한다.

실제 설치된 Relay나 Claude 세션에는 적용하지 않는다. Vimium의 Esc 가로채기를 확인하는 issue #58은 별도 미해결 항목이며 이번 검증으로 종료하지 않는다.
