# 읽을 수 있는 작업 화면

2026-09-06. 기준: main `fef5681` (PR #59–62 병합 확인).

## 배치 결정

- 사이드바는 좌우 여백 14px와 헤더 높이 40px를 공통으로 사용한다. 상태 정보와 아바타·ID는 함께 줄바꿈하며 Requests의 중복 대상 ID 표시는 간소화한다.
- 상태별 작업 그룹과 Requests는 모두 접기·펼치기를 지원하며, 오른쪽에 개수와 꺾쇠를 나란히 둔다. Messages는 헤더 전체가 접기·펼치기 버튼이며 꺾쇠를 맨 오른쪽에 둔다. Show history/Hide history는 입력창이 아닌 채팅 내역 영역 오른쪽 위에 표시하고, 메시지와 겹치지 않는 공간을 확보한다. 과거 대화·요청의 포함 여부를 제어하며 Messages를 접으면 함께 숨긴다. 작업 그룹은 접힌 상태를 기억하고 접혀 있어도 개수를 계속 갱신한다. Needs attention은 확인 필요를 뜻하는 황색 계열, Running은 파랑, Queued는 회색, Done은 초록으로 제목과 개수 배지를 맞춘다. 실제 오류 작업의 빨간 상태 배지는 유지한다.
- Requests를 왼쪽 사이드바 안의 접이식 섹션으로 배치한다. 기본 사이드바 너비는 앱 너비의 21.4%이며, 채팅과 Requests는 각각 본문 높이의 41.5%로 시작한다. 드래그한 크기도 비율로 저장해 창 크기가 바뀌어도 유지한다. 이전 픽셀 기반 저장값은 새 기본 비율로 한 번 전환하고 패널 열림 상태는 보존한다. Requests를 접으면 작업 목록 공간을 확보하고, 펼친 상태에서는 Requests 높이를 별도로 조절한다. 목록과 요청 이력은 각각 독립적으로 스크롤한다.
- Requests는 옅은 배경과 응답 필요 수로 행동 대기 영역임을 구분한다. Requests 내부의 Open/All 필터는 두지 않는다. 기본적으로 닫히지 않은 작업의 요청과 작업 생성 전 미확정 요청을 표시하고, Messages 헤더의 History를 켜면 보관된 요청·대화도 함께 표시한다. 보관된 요청은 Archived로 표시하고 응답·재시도 조작과 알림 수에서 제외한다. 요청 행은 구분선 없는 안을 사용하며 왼쪽 강조선과 추가 들여쓰기를 없앤다. `More`는 실제로 내용이 잘린 행에만 표시한다. Requests를 접으면 목록을 숨긴다. Messages는 아래쪽 대화 영역을 사용하며 Requests에서 agent 대화로 바로 이동할 수 있다.
- Agents 사용량/상한, queued, Today 토큰 추정치는 relay 로고가 있는 상단 헤더에 한 줄로 표시한다. 브라우저 favicon과 헤더에는 같은 Relay 아이콘을 사용한다. 작은 화면에서는 탐색·설정 조작 공간을 침범하지 않도록 반응형으로 표시한다.
- Messages 헤더는 펼치기·접기 버튼이다. 접으면 40px 헤더만 남고 메시지·입력창·높이 조절선은 숨겨진다. 다시 펼치면 이전 대화 높이와 초안을 유지한다. 대화 내용과 입력 영역은 가용 폭 안에서 최대 1200px를 사용하고, agent 메시지는 그중 최대 86%, 질문 카드는 최대 860px까지 넓혀 긴 내용을 읽기 쉽게 한다.
- 좁은 화면에서도 작업 목록과 Requests에 접근할 수 있어야 하며, 패널 전환 시 메시지 DOM을 교체하지 않아 초안과 Ask 상태를 유지한다.
- 대화 영역의 기본 높이는 헤더·상태 배너를 제외한 작업 영역의 45%를 기준으로 한다. 모바일(화면 너비 640px 이하)에서만 최대 520px·작업 영역의 55%로 제한하고 캔버스에 가능한 한 180px 이상을 남긴다. PC에서는 이 상한 없이 사용자가 조절한 높이를 사용하되 캔버스에 최소 120px를 남긴다. 낮은 창에서는 미니맵 높이를 제한한다. 캔버스 너비 640px 이하 또는 높이 280px 이하에서는 상태 범례를 숨겨 작업·조작 공간을 확보한다. 저장한 픽셀 높이는 변경하지 않고 화면에 맞게 표시한다.
- 경계선 더블클릭 또는 Command palette의 `Reset conversation height`로 반응형 기본 높이를 복원한다. 다른 패널 크기만 저장해도 대화 높이가 고정되지 않도록 기본값은 `null`이다.

## 작업 상세와 대화 탐색

- Task detail은 기본적으로 닫힌다. 그래프 노드 또는 작업 목록을 선택하면 캔버스 안의 오른쪽 패널로 열리고, 닫으면 그래프에 공간을 돌려준다. 새로고침 시 저장된 작업 선택은 복원하되 상세 패널은 열지 않는다. 외부 세션 상세도 선택할 때만 연다.
- 사용자가 보낸 메시지와 그 접수·처리 표시는 오른쪽, agent가 보낸 질문·결과와 Relay 응답은 왼쪽에 정렬한다. agent 발신자는 이모지 아바타와 작업 ID를 묶은 pill로 표시하고, 시스템 발신자는 `Relay`로 표시한다. Requests에서는 요청의 상태와 이력을 훑고, Messages에서는 질문과 응답을 대화로 읽는다.
- 응답 선택지는 Requests에 중복 표시하지 않고 Messages에서만 질문 본문과 하나의 카드로 묶어 질문과 답변 조작의 관계를 분명하게 한다. 긴 선택지는 카드 안에서 줄바꿈한다.
- 메시지 본문은 공통 안쪽 여백과 줄높이를 사용한다. 메시지·입력 힌트·입력창의 좌우 기준선을 맞추고, 실제 채팅 영역 너비에 따라 여백과 말풍선 폭을 조절한다. 입력창과 Ask·Send 버튼은 기본 40px, 채팅 너비 420px 이하에서는 44px 높이를 사용한다.
- Requests 제목을 누르면 해당 agent의 가장 최근 메시지로 이동하고 키보드 포커스와 잠깐의 강조 표시를 준다. 이는 특정 과거 요청 시점의 메시지로 이동하는 기능이 아니다. 여러 agent로 분할된 요청은 각 작업 칩으로 개별 agent의 메시지를 찾는다. 아직 메시지가 없으면 그 사실을 알린다. 좁은 화면에서는 Messages를 볼 수 있는 상태로 전환한다.
- agent별 이모지 아바타와 색은 UUID 기반 해시로 정한다. 새로 렌더링하거나 새로고침해도 같은 agent의 요청·대화·노드·목록 표시가 일치한다. 이모지와 ID를 하나의 pill로 묶어 알아보기 쉽게 표시한다. 유한한 이모지·색 조합은 중복될 수 있으므로 작업 ID를 함께 표시하며 색만으로 구분하지 않는다.

## 그래프와 목록의 역할

상단 명령·알림·설정 버튼은 34px 조작 영역과 18px 아이콘을 사용하고, 열림 상태를 색과 `aria-expanded`로 표시한다. 알림·설정은 380px 패널을 가용 화면 안에 배치한다. 각 화면에는 이름이 있는 닫기 버튼을 제공하고 기존 Esc·외부 클릭·포커스 복귀 동작을 유지한다. 설정은 입력 라벨과 프로젝트 폼을 정렬하며, 명령 팔레트와 단축키 편집기는 검색·키보드 힌트·오류·저장 조작을 구분한다. 모바일에서는 패널 내부를 스크롤하고 검색·편집 입력은 16px 글자 크기를 사용한다.

Gateway와 작업 카드의 안쪽 여백·제목 크기·메타데이터 간격을 통일한다. 노드의 이모지와 작업 ID는 하나의 묶음으로 유지하고, 긴 프로젝트 정보만 줄임 처리한다. 줄여 표시한 프로젝트·활동·브랜치 정보는 마우스를 올려 전체 내용을 확인할 수 있다.

상태 범례의 왼쪽·아래 여백과 배율 조작의 오른쪽·아래 여백은 모두 12px로 통일한다. 모바일 화면 또는 캔버스 너비가 640px 이하인 경우에는 배율 조작을 숨기며, 핀치·키보드 확대 조작과 미니맵 보기 전환은 유지한다.

목록은 전체 작업의 상태와 탐색을 담당하고, 그래프는 읽을 수 있는 크기로 현재 작업 주변 관계를 보여준다. 자동 배치는 카드 100% 크기를 유지한다. Alignment 설정은 제거해 화면 정렬을 별도로 선택할 필요가 없게 한다. 부모 카드는 320px, 자식은 300px, 대기 카드는 260px로 넓히고 제목을 최대 두 줄로 표시한다. 열 간격도 함께 넓히며 긴 제목으로 높이가 바뀌는 대기 카드도 실제 높이로 배치한다. Gateway는 대기 카드와 같은 260px 너비의 흰색 실선 카드로 통일한다. 두 카드의 오른쪽 경계를 맞추고 Gateway 연결은 tree/radial 모두 하나의 Bézier 곡선으로 그려 대기 카드와 겹치지 않게 한다. 포인터로 카드를 누를 때는 클릭이 끝나기 전에 포커스 처리로 카드가 이동하지 않으며, 키보드 포커스의 중심 이동은 유지한다. 목록에서 선택한 작업은 최소 100%로 이동하며, 수동 탐색 후 상태 갱신이 시점을 빼앗지 않는다. Home은 전체 관계를 살펴보는 축소 개요를 보여준다. 60개 작업에서도 전체 범위가 들어가도록 개요 배율은 20% 아래까지 허용한다. 미니맵 모서리 버튼은 전체 보기와 선택한 작업 또는 첫 작업을 읽기 가능한 크기로 보기를 전환하며, 현재 상태는 버튼의 pressed 상태와 접근성 이름에 반영한다. 미니맵은 hover 또는 키보드 focus 시 데스크톱에서 172→260px, 좁은 화면에서 128→200px로 확대하되 캔버스 크기로 제한한다. 확대된 지도에서도 표시 좌표와 이동 좌표를 동기화한다. 별도의 Read 버튼은 두지 않는다. 오른쪽 아래에는 `−`, 현재 배율, `+` 조작을 나란히 배치하며 배율을 누르면 100%로 돌아간다. 배율 조작의 기본 배경·테두리는 없애고 옅은 그림자로 구분한다. 일반 휠·트랙패드 스크롤은 그래프를 가로·세로로 이동하고 Shift+스크롤은 가로 이동한다. 확대·축소는 Ctrl/Meta를 누른 스크롤이나 브라우저가 해당 수정키로 전달하는 핀치 제스처로 수행하며, 포인터 위치를 기준으로 한다.

| 대안 | 판단 |
|---|---|
| 전체 그래프를 항상 맞춤 | 세션 증가가 곧 글자 축소로 이어져 기본 표시에서 제외 |
| 그룹 접기 | 부모·자식 관계는 이미 묶여 있으나, 접힌 자식의 질문·오류와 선택 상태를 표현하는 추가 규칙이 필요하므로 이번 범위에서 보류 |
| 선택한 작업만 필터링 | 관계 비교가 끊기므로 기존 주변 작업 강조와 목록 이동을 활용 |
| 그래프를 목록으로 교체 | 기존 상태별 목록과 중복되므로 두 영역의 역할을 분리 |

전체 작업을 동시에 읽는 화면은 아니다. 많은 작업은 목록으로 이동하고 전체 관계는 개요로 확인한다. 렌더링 가상화나 수백 노드 성능 최적화는 이 변경에 포함하지 않는다.

## 재현

```sh
RELAY_UI_AUDIT_PORT=18814 bun scripts/ui-audit/serve.ts
bun test web/test
bun run build:web
bunx tsc --noEmit
bun test
```

합성 서버는 현재 worktree의 HTML/JS/fixture를 매 요청마다 읽으며 실제 서버 어댑터를 로드하지 않는다.

- `/`: 질문, 긴 제목, 하위 작업, 외부 세션, 완료 요청
- `/?few`: 2개 작업
- `/?many`: 60개 상위 작업과 하위 작업
- `/?request-layout=plain`과 `/?request-layout=dividers`: 같은 내용과 배치로 행 구분선 유무를 비교하는 합성 옵션이다. 최종 선택은 구분선 없는 `plain`이다.
- `/?history`: 두 agent의 과거 요청·응답 24쌍을 추가한다. 긴 요청 이력의 독립 스크롤과 agent별 최신 메시지 이동을 확인한다.
- `/?empty`, `/?dark`, `/?updates`, `/?slow`, `/?fail`: 빈 화면·테마·반복 렌더·전송 대기·전송 실패
- `?updates`는 반복 렌더이며 상태 변경은 합성 질문 응답과 Stop/Restart/Archive로 확인한다.

브라우저에서 1440×900, 390×844, 736×414를 확인한다. 사이드바 너비와 Requests 접기·별도 높이 조절, 상단 사용량 요약과 favicon 일치, 독립 스크롤, 메시지 좌우 정렬, 요청에서 메시지로 이동·포커스·강조, agent 표시의 일관성을 검증한다. Messages 접기·다시 펼치기와 Requests 구분선 유무도 비교한다. 상세 기본 닫힘·선택 시 열기·닫은 뒤 공간 반환·새로고침 시 닫힘도 확인한다. 기존 검증 대상인 헤더 정렬과 대화 높이, 노드 포인터 클릭·키보드 선택과 카드 너비·두 줄 제목·열 간격, 미니맵 전체/읽기 전환과 배율 조절, 전체 요청 이력과 상태 구분, 질문 카드와 응답, 초안·Ask, Cmd+K/Esc, 모바일 전환을 유지한다. 기존 저장 높이와 초기 설정 없는 화면은 구분한다. 이 목록은 검증 계획이며 이번 수정의 통과 결과를 의미하지 않는다.

실제 설치된 Relay나 Claude 세션에는 적용하지 않는다. Vimium의 Esc 가로채기를 확인하는 issue #58은 별도 미해결 항목이며 이번 검증으로 종료하지 않는다.

가로 휠과 트랙패드 가로 스크롤은 캔버스를 이동하며 Shift+휠도 좌우 이동으로 처리한다. 일반 세로 휠과 Ctrl/Meta 수정 키를 사용한 확대·축소는 포인터 중심을 유지한다.


## 실제 Claude 목록과 대화 이력

- `claude agents --json --all`에 남은 세션은 `done`·`stopped`·`failed`도 표시한다. 이미 보이는 Relay 작업과 같은 세션은 중복 노드를 만들지 않고, 나머지도 Running·Idle·Done 등 같은 상태 그룹에 합산한다. 완료된 세션은 목록에서 제거될 때까지 남는다. 동일 세션 UUID의 이모지를 목록·노드·상세 화면에 공통으로 표시한다.
- 세션 표시와 중지 권한은 별개다. 종료된 세션과 다른 Relay 인스턴스가 소유한 세션에는 중지 버튼을 제공하지 않는다. 기존 소유권 검사와 자동 정리 동작은 유지한다.
- 작업이 없어도 Claude 세션이 있으면 첫 세션을 기본 시점으로 삼고 빈 캔버스 안내를 숨긴다. 헤더의 `Workers`는 실행 중인 Relay 작업 슬롯 수이며, Claude의 완료 세션 수와 구분한다.
- `done` 작업은 현재 대화에 남는다. 닫힌 작업, 누락된 작업, 보관된 상위 작업의 하위 대화는 History에서만 보인다. 분할 요청은 남은 작업이 하나라도 있으면 유지한다. 작업에 연결되지 않은 미확정 요청은 임의로 완료 처리하거나 숨기지 않는다. 확인 대기 요청의 재판단 버튼은 Recheck routing, 실제 실패 재시도는 Retry로 표시한다.
- History는 데이터 삭제나 보관 상태 변경 없이 Requests와 Messages의 표시 범위를 함께 전환한다. 종료된 질문은 과거 문장으로 읽을 수 있으나 다시 응답할 수 없다. 작업 닫힘 이벤트나 스냅샷 변경 시 표시 범위를 즉시 갱신한다.
